# Paseo plugin host contract

What Paseo 0.11 to 0.14 actually give a plugin at runtime. `ppd check` tests the rows marked (checked).

| Area | Contract | What to do |
| --- | --- | --- |
| Client modules (checked) | Only `react`, `react/jsx-runtime`, `react-native`, `@tanstack/react-query`, `zod`, `@getpaseo/plugin`, `@getpaseo/plugin/client`, `/client/ui`, `/client/react-native`. Any other runtime require throws `Module "<name>" is not available in plugin client code`. Other npm packages are fine only if esbuild bundles them fully. | Keep host modules in `devDependencies`. |
| Host module versions | The app supplies React and its paired React Native renderer. Local development versions provide types; an SDK peer range is not a runtime compatibility guarantee. React Native minor-series updates can break APIs. | Match the oldest supported host, review React/RN/SDK updates together, and run ordinary dependency resolution and typecheck before host checks. Do not auto-merge a new RN series or bypass peers to call it compatible. |
| Gestures (checked) | No `react-native-gesture-handler` or `react-native-reanimated`. | Build pinch and double tap from `onResponder*` / `PanResponder` and `Animated`. |
| Safe area (checked) | Plugin panels get no safe-area insets (getpaseo/paseo#5866, PR #5867). The Android nav bar can cover the last rows. | Pad the bottom yourself; runtime-detect a host `useSafeAreaInsets` export if one appears. |
| Horizontal scroll | A plugin horizontal `ScrollView` is not registered with the host, so a fast right swipe on a zoomed page opens the mobile sidebar. | Known limit; keep horizontal panning short or behind a mode. |
| Icons (checked) | Contribution `icon` fields are Lucide names before 0.13.0; from 0.13.0 also `{ svg }` (no scripts, styles, event handlers or external hrefs) or a component (not for attachment sources). They are validated at registration: an unknown name throws, and the app then drops the whole plugin client (every contribution, not only that item) with just a console warning. `Icon` from `/client/react-native` renders nothing for an unknown name. No `lucide-react-native` import. | `ppd check` checks names against the installed app's Lucide set; `ppd install` and `ppd web` report a rejected client. |
| Client registration (checked) | Contribution ids match `/^[a-z][a-z0-9-]*$/` and are unique per kind; `context` and callbacks are validated; file panel selectors list extensions without dots and plain filenames, no paths or wildcards; the factory must return a cleanup function. Any violation drops the whole client, like an unknown icon. | `ppd check` applies the rules of the checked app version. |
| Paseo 0.13 client contract (checked) | 0.13.0 added `client.addFilePanel` and `client.addAgentPanel`, made workspace panel `context` optional, and accepts translated labels and `{ svg }` or component icons. On an older app the new methods are undefined and the rest throws at registration, so the whole client is dropped. Apps below `requirements.paseo` skip the plugin. | Declare `"paseo": ">=0.13.0"`, or guard with `typeof client.addFilePanel === "function"`. `ppd check` warns when the oldest app the range admits would reject the client. |
| Cleanup (checked) | The server contribution must return a cleanup too; it runs when the plugin child shuts down (reload, disable, remove). A server, socket or interval it leaves open can keep the old child alive or its port busy for the next load. | Close everything you open; `ppd check` warns about handles left open after cleanup. |
| Hermes (checked) | iOS and Android evaluate the client bundle from source on Hermes. Class syntax fails to parse (getpaseo/paseo#5783), including classes inside bundled dependencies. Paseo lowers async/await for you. | Functions and closures instead of classes; check dependencies too. |
| Server bundle (checked) | Compiled to one CJS string and `eval`'d in a plugin subprocess. Bare requires other than host modules and Node built-ins resolve from Paseo's install, not the plugin. WASM must be inlined (a 12.6 MB bundle parsed in about 60 ms). No native addons, no file-path WASM, no assumption of system binaries. | Pure JS/WASM dependencies, bundled. |
| Git installs (checked) | The manifest `build` runs in a fresh checkout before compile. Runtime packages must be in `dependencies` with a committed lock and `["npm", "ci", "--omit=dev", "--ignore-scripts"]`. | `ppd install --git` exercises this path. |
| Type walk (checked) | Paseo <= 0.11.4 type-walks installed packages; `@types/node` 26 pulled in `node:stream/iter` and failed installs (getpaseo/paseo#7145). | Pin `@types/node` to `~22` (`paseo plugin init` pulls in 26.x, so add the pin explicitly). |
| RPC timeout | 30 s per RPC (`REQUEST_TIMEOUT_MS`). Handlers get no abort signal (hooks do get `context.signal`). After a timeout the handler keeps running and holding memory and concurrency. | Deadline every heavy job (`Promise.race`), cap input sizes, test worst-case fixtures with `assertWithinRpcBudget`. Synchronous WASM cannot be interrupted. |
| Crashes | A crashed plugin child is not respawned (getpaseo/paseo#6821). One out-of-memory parse takes the plugin down until `paseo plugin reload`. | Size and decompression caps before parsing; stream large formats. |
| Response size | Direct websocket messages cap at 100 MiB; clients behind the relay should budget well under 32 MiB. Large base64 images add up fast. | Page or chunk responses; budget bytes per response. |
| MIME and previews | Daemons before 0.13.0 label many binaries, PDFs included, `application/octet-stream`. From 0.13.0 a file panel (`client.addFilePanel`) renders the file tab for the extensions and filenames it claims; before that, plugins have no previewer hook (getpaseo/paseo#3109, #5930). | Detect formats by magic bytes; on 0.13.0 and later register a file panel, otherwise provide your own entry points (panel, Command Center item, slash command). |
| Media | No native video primitive (#4562). Host `playAudio` exists from 0.11.2. | Plan media features around what the host exposes. |
| Theme and layout | Color every `Text` from `theme.colors`; size layout from `layout.compact`. No HTML elements, no `className`. | Test both `ppd web` viewports. |

`ppd check` does not run TypeScript. Its successful compiler and Hermes checks do not prove that newer local
types describe the supported host. Hermes discovery prefers the plugin's local React Native package before
`PASEO_SOURCE`; use explicit `HERMESC` and `HERMES` from the target host when checking an older native runtime.
